# 街景定位准确度优化路线图（供选择）

> 版本：v1 · 2026-02 · 基于现有评估数据与代码架构
> 目标读者：需要决定"下一步投入哪个方向"的你

---

## 1. 现状基线（先认清我们在哪）

| 指标 | 数值 | 数据来源 |
|---|---|---|
| 国家级 Top1 准确率 | 71.9% ~ 75% | KartaView 独立评测集 32 张（巴黎/罗马/马德里/维也纳，与画廊无重叠） |
| 城市级 Top1 准确率 | ~78% | 同上（城市命中的前提是国家对，故更高） |
| 高置信段（≥0.7）命中率 | ~100% | 校准评测：模型自信时基本都对 |
| 无证据兜底 | 100% 出结果 | 32 张全量扫描：0 失败、0 空候选（修复 no-cn 误删后） |
| 平均耗时 | 5~9s（flashx 正常期） | 平衡模式实测 |

**核心洞察**：系统"下限"（永不失败、永远有结果）已经立住；**"上限"（准确率）是下一个战场**。国家 72% 意味着约 1/4 的图被定位到错误国家——这是最值得投入的方向。

### 现有能力盘点（准确度相关）
- LLM 线索提取（glm-4v-flash / glm-4.6v-flashx / glm-4.6v 三档，双采样合并）
- Geo-KB 交叉筛选（89 国 × 11 维度证据矩阵）
- MixVPR 视觉先验（**仅 4 城 20 张画廊**：布达佩斯/基辅/华沙/布拉格）
- 街景索引检索（**仅罗马 1 城 247 张**，实测命中 0.98 街道级）
- KartaView 街景回查 + LLM 复检（确认×1.15+0.1 / 否决×0.35）
- 时区昼夜校验（B3）、EXIF 快路径、7100 城表、除大陆范围

### 常见错误模式（观察总结）
1. **中欧/东欧小国互混**：维也纳被认成波兰/德国/捷克（模型对"中欧感"有概念，但对国界模糊）
2. **无文字图只能靠景观**：森林/山地/乡村图，线索维度只剩植被+地形，可区分度低
3. **城市级错误但国家级正确**：国家对了、城市猜错（占比 ~20%，靠"城市档案"可救）
4. **模型间结论不一致**：同一张维也纳图，flash 判波兰、flashx 判奥地利——说明单模型有噪声，融合可降
5. **LLM 对"少见城市"知识不足**：未收录城市靠估算坐标，精度约 ±100km

## 2. 优化方向清单（按"性价比"分组）

### 🥇 A 组：高性价比（推荐优先做）

#### A1. 评测集扩充 + 错误归因（地基工程）
- **做法**：把评测集从 32 张扩到 100+ 张（每大洲至少 10 张，含难图：乡村、无文字、山地、雪景、沙漠）；每次改动后跑全套并输出"错误清单"（国家错/城市错/超时/降级）
- **预期收益**：没有它，所有优化都是"拍脑袋"。A 组其余项目全部依赖它做验收
- **成本**：低（数据收集 ~半天 + 跑批脚本已有 `scripts/evaluate.py`）
- **风险**：无

#### A2. MixVPR 画廊从 4 城扩到 20 城
- **做法**：每城收集 10~20 张街景图（可从 KartaView 按城市拉取，脚本化），覆盖各大洲代表性城市；`build_centroids.py` 已有基础
- **预期收益**：视觉先验从"4 城盲区"变为"20 城粗筛"。先验命中时直接给出城市级候选，且与 LLM 结论可交叉验证（互相印证升权、矛盾降权——**先验+LLM 双通道投票**）
- **成本**：低-中（图源：KartaView 免 key；网络本机可达）
- **风险**：画廊相似度过高城市（如布拉格 vs 布达佩斯）会互相干扰 → 需要相似度阈值校准

#### A3. 双模型融合（flash + flashx 并行投票）
- **做法**：平衡模式现在只跑 flashx；改成 flash + flashx **并行**各跑一次（耗时≈单次），两国/城假设取并集：两模型都说 A → A 权重 ×1.6；只有一方说 A → 降权。5 张内的快速一致性检查
- **预期收益**：实测两模型结论不一致率约 20-30%（维也纳图 flash 波兰 / flashx 奥地利）。融合能显著压掉单模型噪声，预计国家准确率 +5~8 个百分点
- **成本**：低（代码改动小；API 成本 ×2，但 flash 便宜；并发上限内可行）
- **风险**：平台繁忙时双模型都超时 → 现有降级链兜底，无额外风险

#### A4. 城市档案 Top300（让"城市级猜测"有依据）
- **做法**：Geo-KB 增加**城市维度档案**：300 个主要城市 × {国家, 经纬度, 气候带, 典型植被, 建筑风格关键词, 地标, 车牌/方言特征, 时区}。LLM 给城市假设后，用档案做"城市特征交叉验证"：气候/植被/地形与场景描述匹配的城市升权
- **预期收益**：直接打"城市级错误"（错误模式 3）。城市 Top1 从 78% → 目标 85%+
- **成本**：中（数据整理是大头，300 城 × 8 字段；可用 LLM 批量生成后人工抽检）
- **风险**：档案字段错 → 反而降权 → 需要抽样校验

### 🥈 B 组：中等性价比

#### B1. 提示词工程升级（少样本 + 证据链）
- **做法**：`CLUE_EXTRACTION_PROMPT` 现在只有 1 个示例。加 5~8 个多样化少样本（乡村/城市/山区/沙漠/雪地各 1 个完整 JSON 示例）；强制"先列 5 条可见证据 → 再给结论"的两段式输出；城市名输出**英文规范名**（中文名经常匹配不上城市表，之前"清迈/大台町"都踩过）
- **预期收益**：+2~4 个百分点（少样本对弱模型的提升明显，flash 系尤甚）
- **成本**：低（纯文本工作，改完跑 A1 评测集即知效果）
- **风险**：输出变长 → 耗时略增；需防模型"背答案"

#### B2. 复检阈值校准（verify 现在过于"一票否决"）
- **做法**：当前"确认×1.15+0.1 / 否决×0.35"是拍脑袋值。做一次标定实验：对评测集跑复检，统计"否决正确率"——发现 KartaView 附近照片因视角/季节不同被误否决（巴黎图被 10% 置信否决过）。校准：低置信否决（<0.5）不降权、否决从 ×0.35 放宽到 ×0.6、增加"存疑"档
- **预期收益**：减少"明明对了被复检打下去"的假阴性；+2 个百分点
- **成本**：低（调参 + 评测）
- **风险**：无

#### B3. 街景索引扩到 5 城
- **做法**：罗马索引已验证（命中 0.98 街道级）。扩展到巴黎/马德里/维也纳/柏林等评测城（`build_index.py` 已有；图源 KartaView 批量拉取）
- **预期收益**：对"有索引城市"的图，街道级命中大幅提升候选精度；与复检联动（有真实街景图可对照时复检才可靠）
- **成本**：中（每城几百张图下载 + 索引构建 + 存储）
- **风险**：低

#### B4. 可见文字强化（OCR 双通道）
- **做法**：文字是最高置信线索，但 LLM 在整图分析时容易漏小字。对 balanced/deep 模式：把图**放大裁成 4 象限**，额外跑一次"只看文字"的轻量提问（flash 即可），把转写文字并入 visible_text 再走 Geo-KB
- **预期收益**：路牌/招牌类图（占比可能 20-30%）直接锁定国家甚至城市；+3~5 个百分点
- **成本**：中（多一次 LLM 调用 + 4s 左右耗时，需控制在模式预算内；deep 模式做，balanced 可选）
- **风险**：耗时超预算 → 需裁剪；对无文字图零收益（但无损失）

### 🥉 C 组：远期/重投入

#### C1. 跨平台多模型（通义/豆包/千帆/混元 key → 投票）
- **做法**：接入第二家平台的视觉模型，与智谱结果做硬投票（两家都选 A → A；分歧 → 取置信度高者+降权）。同时缓解智谱"繁忙期"单点依赖
- **预期收益**：跨厂商噪声更低，预计 +3~6 个百分点；顺带解决平台稳定性
- **成本**：中（需要一个新平台的 API key——你之前没提供，如有通义/豆包 key 可以立刻做）
- **风险**：各家 JSON 输出格式差异（解析层已抽象，风险可控）

#### C2. 用户反馈回路
- **做法**：结果页加"👍 定位正确 / 👎 不对，实际是 X"按钮，落库。攒 500 条后：① 校准置信度 ② 做错误模式分析 ③ 筛选"高错误率图片类型"针对性优化
- **预期收益**：长期数据飞轮；短期无直接收益
- **成本**：低（前后端小改动）
- **风险**：用户不点 → 数据稀疏；需防误标

#### C3. 太阳方位角/季节先验
- **做法**：EXIF 时间 + 拍摄方向 + 太阳方位 → 验证道路走向与南北半球（B3 已有昼夜校验的雏形）
- **预期收益**：+1~2 个百分点（仅对有 EXIF 时间的图有效，多数街景图无 EXIF）
- **成本**：中（地理计算库 + 方向推断）
- **风险**：收益上限低

## 3. 推荐组合（如果只选 3 个）

**路线 ①（本周可做，纯软优化，零外部依赖）**
> A1（评测集 100 张）+ A3（双模型融合）+ B1（提示词升级）
- 预计国家准确率 72% → **80%+**，总工作量 1~2 天

**路线 ②（下周，需要一点数据工程）**
> A2（画廊 20 城）+ A4（城市档案 Top300）+ B2（复检校准）
- 预计城市准确率 78% → **85%+**，总工作量 2~3 天

**路线 ③（远期，需要你的决策）**
> B3（索引 5 城）+ B4（文字强化）+ C1（跨平台 key）
- 需要：另一个平台的 API key；或接受 KartaView 批量下载的存储开销

## 4. 建议的推进方式

1. 先做 **A1 评测集扩充**（半天）——它给所有后续方案提供"尺子"
2. 在尺子上跑 **A3 双模型融合 + B1 提示词**（各 2~4 小时），立刻看到数字变化
3. 你提供任一其他平台 key → 立刻加 **C1**；不提供 → 用 **A2 画廊扩充**替代
4. 每步改动都跑评测集对比（国家 Top1 / 城市 Top1 / 降级率 / 平均耗时 四指标），避免"感觉变好了"陷阱
