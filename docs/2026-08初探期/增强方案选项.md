# 超越纯 LLM：增强方案选项单

> 现状：工具 = 多模态 LLM（GLM-4.6V）凭训练记忆分析街景 → 国家级精度（实测 3 中 1）。
> 问题：LLM 记不住街道级坐标、无法比对像素、会自信地编造城市。
> 目标：给 LLM 装"外部器官"——数据库 / 工具 / 第二模型，把精度推进到城市级 → 街道级。

---

## 方案总览

| 方案 | 一句话 | 新增能力（相对纯 LLM） | 解锁精度 | 工作量 | 依赖 |
|---|---|---|---|---|---|
| **A. 街景影像向量库**（FAISS） | 把真实街景照片建成可检索的图片数据库 | **像素级匹配**（LLM 做不到） | 街道级 | 2~3 周 | Mapillary token、ONNX 嵌入、磁盘 |
| **B. 地理事实知识库**（Geo-KB） | 把国家档案（路牌/车牌/语言/驾驶侧…）建成 LLM 可查的事实库 | **确定性事实核查**，消除幻觉国家 | 国家级→城市级 | 1~2 周 | 无（自建 SQLite 档案 + OSM） |
| **C. VPR 模型第二意见** | 用亿级街景训练过的专用定位模型做独立判断 | **地理先验**（不需要自建库） | 城市级 | 1 周 | PyTorch + 预训练权重（CPU 可跑） |
| **D. Agentic 工具调用** | 给 LLM 配工具：地理编码/维基/WikiData/街景查询 | **多跳外部世界知识**（OSINT 式查证） | 城市级 | 2~3 周 | 多个免费 API |
| **E. 微调专用模型** | 用带地理标签的街景图微调小 VLM | **领域专精**（超越通用模型） | 城市级 85%+ | 3~6 周 | GPU（可租 RunPod） |

---

## 方案 A：街景影像向量库（"图片数据库"）

**原理**：这是最符合"加数据库"直觉的方案——把 Mapillary/KartaView 的真实街景照片用本地嵌入模型（DINOv2/StreetCLIP/MegaLoc）转成向量，建成 **FAISS 向量库 + SQLite 元数据**。查询时：输入图 → 同一嵌入模型 → 向量最近邻检索 → 输出"长得最像的 N 个真实地点"。

**新增能力**：像素级比对。LLM 无法"记住"一个街角的像素，向量库可以。这是从"猜"到"认"的质变。

**流程**：
```
目标城市 → Mapillary API 下载街景（ZenSVI 批量）
        → ONNX 嵌入（CPU 每张 1~5s）
        → FAISS 索引 + SQLite（坐标/时间/来源）
查询：输入图 → 嵌入 → FAISS top-50 → 空间聚类 → 候选点
     → 候选街景图与查询图一起送 LLM 复检（LLM4VPR 范式）
```

**关键数字**：
- 单城市 ~1万~10万张，嵌入后 0.5~2GB，FAISS 检索 <100ms
- 精度 = 覆盖密度：索引过的城市可到街道级；没索引的地方无能为力（诚实降级）

**成本**：Mapillary token（免费申请）+ 建库计算（城市级小时级）+ 磁盘。**注意**：中国覆盖极少的客观限制。

**参考**：Netryx（Google 街景建库检索）、locus（建筑级匹配）、"10M 街景嵌入"实践帖、LLM4VPR（LLM 对检索结果复检重排）。

## 方案 B：地理事实知识库（"查字典"）

**原理**：GeoGuessr 高手靠的不是记忆，是"**线索→国家**"的对照表：红白路桩→哪些国家、蓝底白字路牌→哪些国家、黄底车牌→英国/卢森堡…。把这些整理成结构化档案库（SQLite：国家/地区 × 线索维度），LLM 提取线索后**确定性查表**，而不是靠模型回忆。

**档案维度**（每国一行）：
```
语言/文字体系 | 驾驶侧 | 路牌样式 | 车牌格式与颜色 | 道路标线
货币 | 电话区号 | 时区 | 电网/插座 | 邮筒颜色 | 常见建筑类型
限速单位(km/h vs mph) | 路缘石/路桩样式 | 公交样式 | 车牌照底色
```

**新增能力**：**确定性事实核查**——LLM 说"这像西班牙"，查表发现"红白路桩→葡萄牙、西班牙、波兰…"，系统可以**交叉筛选**：多条线索同时命中的国家大幅缩圈，并反驳 LLM 的幻觉。另有 OSM 辅助：城市多边形、路网密度、边境距离。

**流程**：
```
LLM 线索提取（已有）
   ↓
线索 → Geo-KB 查表：每条线索命中国家集合 → 交集/加权 → 候选国家重排
   ↓
LLM 带着"事实清单"二次推理（"线索A支持X国，线索B排除X国"）
   ↓
确定性输出：国家级结论 + 证据矩阵（哪条线索指向哪国）
```

**成本**：几乎为零（SQLite + 人工整理 200 国档案，可社区协作）；OSM 数据免费。**耗时 1~2 周**，是**性价比最高的第一步**——直接消除"自信地错"的根因，把国家级精度做扎实。

**参考**：GeoGuessr 玩家社区知识体系（geotips）、OSINT 手册（Bellingcat 的"路牌/车牌识别"章节）。

## 方案 C：VPR 模型第二意见（"请专家会诊"）

**原理**：MegaLoc/MixVPR/EigenPlaces 等专用视觉定位模型，在**数亿张带 GPS 的街景图**上训练过（比任何 LLM 见过的街景都多）。让它在本地 CPU 跑一遍，给出"全世界哪里最像"的先验分布，与 LLM 假设**加权融合**。

**新增能力**：独立的地理先验——不需要自己建库，模型自带"亿级街景记忆"；LLM 猜国家、VPR 出坐标，交叉验证。

**流程**：
```
输入图 → VPR 模型（本地 CPU，1~3s）→ 全局候选 + 相似度热力图
       → 与 LLM 国家假设融合（贝叶斯式加权）
       → 命中区域 → 结合方案 A 的街景回查确认
```

**成本**：PyTorch + 预训练权重（MegaLoc 约 1~2GB，MixVPR 更小），CPU 可跑，**无需任何数据管线**，1 周可集成。精度：城市级先验可靠，街道级仍需 A 支撑。

**参考**：Netryx V2 用 MegaLoc、statewide ECCV2024 的方法论、gmberton 系列。

## 方案 D：Agentic 工具调用（"配助理"）

**原理**：把 LLM 从"答题者"变成"调查员"——给它工具列表（function calling）：
```
geocode(地名→坐标)         # Nominatim 免费
lookup_wiki(关键词→条目)    # Wikipedia/Wikidata：查地标、查店名、查区号
reverse_geocode(坐标→地名)
overpass_query(区域→道路/POI)  # OSM 空间查询
streetview(坐标→街景图)     # Mapillary bbox 查询
timezone(坐标→时区)         # 交叉验证
```

**多跳推理示例**：
```
LLM："招牌写着 'Café Gloria'"
 → 调 lookup_wiki("Café Gloria") → 命中"格拉纳达的百年咖啡馆"
 → 调 geocode("格拉纳达") → 坐标
 → 调 streetview(坐标) → 拉回街景图与查询图对比 → 确认
```

**新增能力**：**多跳外部世界知识**——店名、地标、区号这些"世界事实"不再依赖模型记忆，而是实时查证。这是把 OSINT 方法论程序化。

**成本**：多个免费 API + 每图 2~5 次额外 LLM 调用（约多花几秒~几十秒、几分钱）；需要设计好工具循环（防死循环、防超预算）。**耗时 2~3 周**。

**参考**：GPT-4V 定位 PoC（gpt-guessr）、LLM4VPR 的 LLM 重排思想、OpenAI function calling 最佳实践。

---

## 方案 E：微调专用模型（"造专家"）

**原理**：AI_GeoDetect 论文实测：StreetCLIP 在 4 城 3716 张测试图上城市 Top-1 **89.4%**，远超通用 LLM。用带 GPS 标签的街景图（H3 res-9 防泄漏划分）微调一个小模型（Qwen-VL-2B 或 CLIP 系），让定位成为它的"专长"。

**新增能力**：领域专精——见过百万张街景后，城市判断接近人类专家，且推理快（<1s）、成本为零（本地）、可离线。

**成本**：训练需 GPU（RTX 3090 级或租 RunPod ~$1/h × 几十小时）+ 数据采集 2~4 周 + 训练与评测 2 周。**适合作为长期主线**，与 A/B/D 并存（作为城市级"快速通道"）。

**参考**：AI_GeoDetect（完整方法论：三模型对比 + H3 划分 + GeoScore）、PIGEON、StreetCLIP。

## 推荐组合路线（分三步走）

```
第 1 步（1~2 周，性价比最高）→ 方案 B：Geo-KB 事实库
   效果：国家级精度做扎实 + 幻觉大幅减少 + 证据矩阵可解释
   产出：国家档案库 + 线索→国家交叉筛选 + 前端证据矩阵展示

第 2 步（2~3 周，核心大招）→ 方案 A：街景影像向量库 + D 的轻量版（geocode + streetview 工具）
   效果：对建库城市解锁"街道级"，对未建库区域用 D 的实时查证兜底
   产出：FAISS 索引构建器 + 检索→复检闭环（LLM4VPR 范式落地）

第 3 步（持续）→ 方案 C（VPR 先验融入）+ 方案 E（微调城市分类器）
   效果：无库城市也有可靠先验；长期用专用模型把成本降到零
```

**推荐先做 B**：它不需要任何外部 key、不需要 GPU、两周内能明显看到"从凭记忆到查字典"的变化，且 B 的档案结构是 A/C/D 都复用的地基（A 的候选要过 B 的事实核查，D 的工具结果要进 B 的档案）。

| 你的偏好 | 推荐 |
