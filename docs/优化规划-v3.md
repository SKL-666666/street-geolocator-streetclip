# 准确度与速度优化规划 v3（纯规划，不写代码）

> 依据：独立评测集 32 张真值图（国家 Top1 71.9~75%、城市命中 75~78%、校准 ≥0.7→100%）、
> 稳定性实测（flash 0 超时 vs 4.6v 2/6 超时）、全管线耗时拆解。

---

## 一、现状瓶颈判断（先分清主次）

| 维度 | 现状 | 瓶颈本质 |
|---|---|---|
| 准确度 | 国家 75%、城市 78% | **数据覆盖不足**（画廊 4 城、索引 1 城、KB 89 国无城市档案）> 模型能力 > 提示词 |
| 速度 | flash 8~10s 稳定 | LLM 生成是绝对大头（6-7s/图）；本地环节全部 <2s |
| 稳定性 | flash 主力后 0 降级 | 已解决；模型变更必须过稳定性门槛 |

**核心判断：准确度的最大杠杆是"数据"，不是换模型。** 换模型的收益上限是"把 4.6v 的能力搬进 flash 的速度"；而数据（档案/索引/评测）的收益是确定性的、可复利的。

---

## 二、准确度优化（按杠杆排序）

### 🥇 A1. 评测驱动（放大一切后续努力的杠杆）
- **评测集 32 → 100+ 张**：KartaView 多城市多场景采样（免费），覆盖：欧洲邻国混淆区、亚洲、拉美、无文字场景、夜景
- **错误归因报告**：每个错误标注原因类别（邻国混淆/无特征/文字误导/模型幻觉/坐标错位）→ 每次优化直接对表改进
- **错误集回灌**：错误图存独立集合，改动后自动回归（已有 evaluate.py 扩展即可）

### 🥇 A2. 知识层补强（性价比之王）
- **城市档案（City-KB）**：给 Top 300 城市加特征档案（地标/建筑风格/气候带/语言/是否沿海/海拔），LLM 城市假设与档案交叉验证——把"国家证据矩阵"的成功经验复制到城市级
- **错误驱动的国家档案补充**：评测显示的中欧混淆（奥/德/捷/波）→ 补高判别维度（车牌字体、路牌细部、邮编格式、电力杆样式、公交涂装）——每个评测错误都变成一条 KB 改进
- **坐标合理性校验**：LLM 估算坐标与城市表/国家边界比对，偏差过大降权（已有 7100 城表可做距离校验）

### 🥈 A3. 检索与验证闭环扩大（街道级的关键）
- **MixVPR 画廊 4 → 20 城**：KartaView 免费拉图（每城 15-20 张），先验覆盖翻 5 倍；城市命中率直接受益
- **FAISS 索引 1 → 10-20 热点城市**：一条命令一城（已就绪），按用户使用频率优先；热点城市街道级定位落地
- **索引共享**：城市索引打包（罗马已验证格式），社区/多机复用

### 🥉 A4. 模型与推理策略（锦上添花）
- **多模型投票（低置信触发）**：仅当 flash 结果低置信（<0.5）时，并行跑 4.6v（关思考）取共识；成本只花在难题上
- **城市常识复核**：LLM 对候选城市做"该城市是否有山地/沿海/XX特征"的世界知识校验（一次轻量调用，纠正特征矛盾）
- **模型选型数据化**：拿到其他平台 key 后，stability_check 批量对比（成功率/超时/准确率/耗时），数据选型

## 三、速度优化（边际收益递减，适度投入）

| 项 | 措施 | 预估收益 |
|---|---|---|
| S1 | Prompt 精简 20%（输出字段限条数、压缩字段说明） | -1~2s |
| S2 | 街景回查与 LLM 复检**并行**（当前串行） | -2~3s |
| S3 | balanced 图尺寸 1024→896 实测对比 | -0.5~1s |
| S4 | 批量并发 3→4（观察限流） | 批量吞吐 +30% |
| S5 | **速度目标定为 ≤10s 稳定即止** | 余力全部投入准确度 |

**原则：8s 已接近感知即时，把省下的精力给准确度，而不是无限压速度。**

## 四、里程碑路线

### 里程碑 1（约 1 周，全免费）—— 数据地基
1. 评测集扩到 100 张 + 错误归因报告
2. 城市档案 Top 300（数据整理，社区知识源）
3. 画廊扩 20 城 + 索引扩 5 城（KartaView 免费）
4. 错误驱动的档案补充（中欧判别维度）
- **预期**：国家 Top1 75→82%+，城市命中 78→86%+

### 里程碑 2（约 2 周）—— 闭环完善
1. 索引扩到 15-20 城（热点优先）
2. 低置信双模型共识 + 坐标合理性校验
3. 城市档案交叉验证上线
- **预期**：热点城市街道级可用；城市命中 90%+

### 里程碑 3（持续）—— 模型与规模
1. 多平台模型对比（需用户提供 key）
2. 多图联合定位
3. 未来本地 GPU 可选：Qwen2.5-VL 量化部署（彻底摆脱 API 波动）

## 五、三条原则（防止走偏）

1. **稳定性门槛先行**：任何模型/提示词变更必须过 stability_check（成功率 100%、超时 0、准确率不回退）才允许上线
2. **评测优先于调参**：先扩评测、归因错误，再动手改——避免"感觉变好了"
3. **数据 > 检索 > 模型 > 提示词**：优化资源按此顺序投入
