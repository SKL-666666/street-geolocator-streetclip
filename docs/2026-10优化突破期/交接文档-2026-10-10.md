## 1. 项目定位与现状

上传一张街景/街拍照片 → 本地模型推断国家 → 城市 → 地图展示 Top3 候选 + 双击纠错。

| 指标 | 当前值 | 说明 |
|---|---|---|
| **国家级准确率** | **~63%**（bench_final 89张） | 纯 StreetCLIP 56.2% + DINOv2检索融合 |
| **城市级准确率** | **~69%**（32张端到端） | StreetCLIP 判城市 + 国界约束 |
| **单图耗时** | **6~10s**（热态） | 首次约14s（含冷启动） |
| 运行方式 | 纯 CPU，本地优先，零 API 成本 | 云端仅可选（自适应VLM复核/城市引擎） |

## 2. 架构总览

```
前端 (Vue3 + Vite + MapLibre)
   │  POST /api/analyze（或 /api/analyze-fusion 融合）
   ▼
后端 (FastAPI + asyncio)  backend/app/
   │
   ├─ pipeline/orchestrator.py   主流程（国家分诊/城市/候选/反馈）
   ├─ geokb/local_engine.py      StreetCLIP 国家+城市、特征复用、城市文本缓存
   ├─ geokb/geo_lookup.py        坐标→国家（国界多边形）
   ├─ retrieval/dino_geo.py      DINOv2 图库检索（融合证据）
   ├─ retrieval/gallery_add.py   用户纠错图 → 入库（方案A）
   ├─ llm/vlm_country.py         云端VLM复核国家（自适应模式）
   └─ api/routes.py              API 端点
```

**核心流程（local 模式）**：
```
图片 → StreetCLIP 编码一次（国家/城市共用）
   ├─(并发) DINOv2 图库检索
   ├─ 分数融合 → 国家 Top3（标定置信 ~40%）
   ├─ margin 分诊（自适应模式低置信调VLM）
   └─ StreetCLIP 在该国城市池判城市 → 候选 → 反馈先验校正
```

## 3. 【重大】近几步操作详解（重点看这节）

### 3.1 D（缩略图修复，基线校准）
**发现**：测试集混入 25 张 KartaView **200×150 缩略图**（非原图），拖累基线虚低。
**修复**：`bench_compare/replace_thumbs.py` 重拉原图（`imageProcUrl` 而非 `imageThUrl`）。
**效果**：StreetCLIP 50.6% → **56.2%**（+5.6pp）。
**教训**：KartaView 拉图**必须用 `imageProcUrl`**，`radius≤300`。

### 3.2 第二级城市引擎：CLIP-B/16 → StreetCLIP
**背景**：原第二级用 CLIP-B/16（570MB 小模型）判城市，StreetCLIP 只判国家。
**A/B 实测**（32张4城端到端）：城市 **43.8% → 68.8%**（+25pp），耗时 -20%。
**实现**：`local_engine.py` 新增 `encode_streetclip / classify_countries_feat / classify_cities_streetclip`；
**图像特征一次编码复用**（国家/城市共用）。commit `5519c30`。
**注意**：cn（中国）模式**仍用 CLIP-B/16**（未重测，保守未动）。

### 3.3 Step4：DINOv2 图库检索融合（国家级 +5.6pp）
**做法**：建带坐标参考图库（`data/dinov2_gallery/`），DINOv2 提特征，检索 Top-K 投票，
以 `score = SC归一分 + α×检索归一分`（α=0.125）融合 → 56.2% → **61.8%**。
**扩库**：85张/13国 → **189张/39国**（覆盖谷歌街景主要区域），→ **62.9%**。
**alpha 细扫**：0.1~0.15 平台最优，**>0.2 反噬**。
**关键文件**：`app/retrieval/dino_geo.py`、`scripts/build_dinov2_gallery.py`。
**关闭方式**：`settings.retrieval_alpha = 0`（省 2.4s/张，代价 -6pp）。

### 3.4 补 29 国（101 → 130 国）
**问题**："第102国必错"——COUNTRIES 只有 101 国，未覆盖的国必被判成最像的101国之一。
**修复**：补全谷歌街景有覆盖但缺失的 29 国（卢森堡/格鲁吉亚/马达加斯加等）→ 130 国，**+1pp**。
**注意**：**GSV照片量加权实测 -5pp**（双重计数），已回退，勿再尝试。

### 3.5 【重大】用户纠错闭环（方案A）
**旧实现的问题**：
- 反馈端点只存 `correct_lat/lon`（数字），但 `feedback_analysis.build_confusion_matrix`
  有 `isinstance(correct, str)` 判断 → **坐标纠正全部被忽略**
- 且旧逻辑是"给国家降权"，会误伤大量正确图

**新实现（方案A）**：双击地图 → 坐标 → 反查真实国家 → **该图作为带标签参考图加入 DINOv2 图库**。
- `app/geokb/geo_lookup.py`：坐标→国家（shapely 国界多边形，回退最近城市）
- `app/retrieval/gallery_add.py`：图+国家 → 写 images/ + 特征增量追加 features.npz + `dino_geo.invalidate()` 热重载
- `routes.py` /feedback：接线，返回 `correct_country`
- `feedback_analysis.py`：改用 `correct_country`（修 bug）
**特性**：你"偏离大才纠"→ 纠正的都是盲区难图 → 每次纠正都在补图库盲区 → **越用越准**。

### 3.6 置信度标定（100% → ~40%）
**问题**：分数归一化后 Top1 恒为 1.0（显示 100% 虚高）。
**修复**：三路标定——检索融合/VLM 融合 ×0.4、裸 CLIP ×1.5，上限 95%，典型 **~40%**；
margin 阈值同步 0.04 → **0.08**。

### 3.7 性能优化（14.2s → 6~10s）
| 优化 | 省时 |
|---|---|
| 城市文本特征**磁盘持久化**（`data/sc_city_text_cache.pt`） | 各国首次 ~2.2s |
| 启动**预热**加载城市缓存 | 冷启动 |
| StreetCLIP编码 与 DINOv2检索 **并发** | ~2.4s |
**剩余瓶颈**：StreetCLIP ViT-L/14 单次前向 ~4s（固有成本，CPU）。

### 3.8 浏览器插件
- `browser-extension/`：MV3 manifest + popup（截图/提交/进度/结果）+ background（右键菜单）
- 后端 CORS 加 `allow_origin_regex` 放行 `chrome-extension://`
- 前端支持 `?task=<id>` 深链直达结果页
- 桌面 `street-geolocator-插件.zip`

### 3.9 UI/交互
- 深色模式（纯黑 `#000` 背景 + 全冷色系），`html.dark` + CSS 变量（`style.css :root`）
- 双上传模式：**串行批量**（无上限，各自出结果）/ **同地点融合**（2~3张并行 → 聚合为一个结果）
- 进度条：真实百分比 + 平滑（向后端 progress lerp）；双模式统一样式
- 地图：`flyTo curve=1.42` 弧线过渡；**无弹窗**（已彻底移除）；双击地图纠错
- 三模式约束：`world` 全量 / `no-cn` 排除中国大陆 / `cn` 独立分支不调 VLM

## 4. 已证伪的路径（勿重复尝试）

| 方法 | 实测 | 结论 |
|---|---|---|
| 换更大 CLIP（ViT-H 986M） | 50.6%（与175M的SC打平） | 参数×6无收益 |
| OSV5M 回归GPS | 37.1% | 回归式弱于文本匹配 |
| MegaLoc 小库检索 | 18% | 需百万级图库 |
| 4模型融合 ORACLE | 57.3%上限 | 错误高度重叠 |
| 剔除 China 候选 | 0 救回 | China是Top1时Top2也不对 |
| 换prompt复核国家 | 净-2（两次） | 同模型盲区不变 |
| 提示词模板 A/B | ±1张噪声 | 无显著收益 |
| 半球约束 | 判别64%，净-3 | CLIP无此能力 |
| 车道方向 | 判别40.4%，净-11 | 低于随机 |
| GSV照片量加权 | 净-5 | 双重计数 |
| OCR/NDVI/标线 | 历史 +0pp | 已证伪 |
| 城市池扩大 | 10城90.6% > 71城84.4% | Top1单调下降 |

**根因**：凡"用 CLIP 额外问一个问题"的优化全部无效——CLIP 对物理线索判别能力弱（与主模型同源）。
