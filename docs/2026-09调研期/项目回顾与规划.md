## 一、项目介绍

### 1.1 一句话定位

上传一张街景/街拍照片 → 本地模型推断拍摄地点（国家 → 城市）→ 地图展示 Top-3 候选。**纯 CPU 运行，零 API 成本也能用**。

### 1.2 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Vite + MapLibre GL | 上传页 / 结果页 / 批量 / 历史 / 设置 |
| 后端 | FastAPI + uvicorn + asyncio | 异步任务队列，单图独立分析 |
| 本地模型 | StreetCLIP (ViT-L/14@336) | 第一级：国家 Top-3 零样本分类 |
| 本地模型 | CLIP ViT-B/16 (open_clip) | 第二级：国家内城市推断 |
| 云端模型（可选） | 智谱 GLM-4.6V-FlashX | 第二级城市，需用户自备 Key |
| 知识库 | 7100+ 城市表 / 国家档案 / 语系字符线索 | 坐标落点与交叉核查 |
| 增强模块 | RapidOCR、Tavily 搜索、EXIF、车牌、气候特征 | 用户可勾选，失败不阻塞主流程 |

### 1.3 架构与数据流

```
┌──────────────────────────────────────────────────────────┐
│ Frontend (Vue3 + MapLibre GL)      POST /api/analyze      │
│   scope: world / no-cn / cn     + enhance_ocr 开关         │
└───────────────────────┬──────────────────────────────────┘
                        ▼
┌──────────────────────────────────────────────────────────┐
│ Orchestrator (FastAPI, asyncio)                          │
│                                                          │
│  【全球模式 scope=world/no-cn】                            │
│   ① StreetCLIP 零样本 → 国家 Top3（本地，免费）             │
│   ② CLIP-B/16 → 国家内城市（或云端 LLM，可选）              │
│   ③ 增强层：EXIF / 5维CLIP视觉特征 / 车牌 / OCR+Tavily      │
│   ④ 用户反馈先验校正（历史反馈 → 错误率高的国家降权）         │
│                                                          │
│  【中国模式 scope=cn】                                     │
│   ① 跳过 StreetCLIP，城市模型直接推断中国城市               │
│   ② 同一套增强层                                          │
│                                                          │
│  预热机制：本地模型加载完成（约 60~80s）才开放上传            │
└──────────────────────────────────────────────────────────┘
```

### 1.4 模型许可

| 模型 | 用途 | 许可 |
|---|---|---|
| StreetCLIP | 国家分类 | **CC BY-NC 4.0（非商用）**；骨干 CLIP 为 MIT |
| CLIP ViT-B/16 | 城市（本地） | MIT (open_clip) |
| GLM-4.6V-FlashX | 城市（云端，可选） | 智谱服务条款 |

> 本表只列**最终管线实际调用**的模型。调研阶段评估过但未采用的（GeoCLIP、OSV5M、DINOv2、SigLIP2、MixVPR、MegaLoc、GeoSpot 等）不在此列。

## 三、故障复盘（2026-09-13 ~ 09-14）

### 3.1 事件时间线（用户视角）

1. 例行清理临时文件后，发现本地项目目录"消失"、`git clone` 报 `Repository not found`
2. 从 GitHub 下载 ZIP 备用
3. 核查后发现：**本地目录完好、git clean、与 origin 同步**——"消失"是 Git Bash 路径解析抖动 + GitHub API 瞬时故障造成的误判
4. 顺手核验时，发现前端页面对 `UploadView.vue` 报编译错误 → 顺藤摸瓜挖出后面一连串问题

> 结论：**没有数据丢失**。最后成功推送是 `d8fdc99`，本地工作区干净且完全同步。

### 3.2 问题一：桌面启动器从未真正工作过

| 项 | 内容 |
|---|---|
| 文件 | `桌面\street-geolocator 快速启动.bat` |
| 现象 | 双击后前端能开、后端无响应；手动敲命令却正常 |
| 根因 | 原文件里 `\backend`、`\frontend` 的 **`\b`、`\f` 被当成转义字符**写入了退格符(0x08)和换页符(0x0C)，路径实际变成 `streetclip⌫ackend`，`cd` 永远失败 |
| 修复 | 改用变量拼路径（`set BS=\` + `%ROOT%%BS%backend`）彻底规避；并加**端口占用清理**（解决此前多实例抢 CPU 导致的卡顿）和**健康检查轮询**（不再盲等 90 秒） |

### 3.3 问题二：前端 UploadView.vue 被删了 100 行

| 项 | 内容 |
|---|---|
| 引入版本 | `d8fdc99`（"5维CLIP视觉特征 + OCR语系简化…"） |
| 现象 | 页面白屏；Vite 报 `[plugin:vite:vue] Element is missing end tag` |
| 根因 | 该提交的编辑脚本把第 26–128 行整块替换成了一个 `"`，script 里的全部函数（`canSubmit`/`submit`/`onDrop`/粘贴监听…）和 template 头部（`</script>`、`<template>`、`upload-wrap`/`modes` 容器）一并消失 |
| 修复 | 从上一版 `b5b1da5` 恢复被删内容，并同步去掉已废弃的 `enableBaidu` 参数 → 提交 `17ecd40` |

### 3.4 问题三：后端 Orchestrator 类结构被破坏（最严重）

| 项 | 内容 |
|---|---|
| 引入版本 | `d8fdc99` |
| 现象 | **每次分析都静默失败**：任务永远停在 `status=running / stage=queued / progress=0`，前端表现为"卡死、转圈没反应"，日志里**没有任何报错** |
| 根因 | 新增的 `_detect_script()` / `_script_matches_country()` 被插在 **class 中间但缩进为 0 行**，直接终结了 `Orchestrator` 类；其后的 `_retrieval_pass`、`_update` 等 **400+ 行方法全被吞进函数体**，不再是类方法 |
| 失败链 | `_run_local_inner` 里 `self._update(...)` → `AttributeError` → 异常在 `asyncio.create_task` 中无人 await，且任务对象被 `self._tasks` 持有不触发 GC 警告 → **静默死亡** |
| 修复 | 删除这两个从未被调用的死函数，恢复类结构；用 AST 校验 **14/14 方法**与 `b5b1da5` 完全一致 |
| 附带修复 | `submit()` 残留 `enhance_baidu` 引用 → 提交直接 500 |

> 这两个函数是**死代码**：全项目无任何调用点，真正的语系判断走 `geokb/lang_script.py` 的 `LANG_CHAR_CLUES`。

### 3.5 问题四：`Image` 从未导入 + 变量名残留

| 问题 | 影响 | 修复 |
|---|---|---|
| `orchestrator.py` 使用 `Image.open()` 但从未 `from PIL import Image` | **车牌识别**与**OCR+Tavily** 全程 `NameError`，被 `except Exception: pass` 吞掉 → 一直静默失效 | 补上导入 |
| 气候块里 `climate_data = classify_all(...)` 之后仍写 `climate[...]` | 气候块的 `NameError` 被吞 → 该块从未生效 | 统一改为 `climate_data` |

### 3.6 问题五：CLIP 视觉特征先验**恒为空** → "+0pp" 结论作废

| 项 | 内容 |
|---|---|
| 现象 | 5 维视觉特征（气候/路面/建筑/驾驶方向/植被）写完并接线后，实测准确率 +0pp |
| 根因 | `climate.py` 的 `priors` 字典键是**关键词**（`desert`/`unpaved`/`wooden`/`left`…），代码却拿**完整提示词**（`"a photo taken in a desert environment"`）去精确查找 `dict.get(prompt)` → **永远命中默认值 `([], 0)`，先验恒为空字典** |
| 修复 | 改为子串匹配（`kw.lower() in prompt.lower()`），24 个提示词中 20 个正确命中先验（余 4 个为设计上无先验的默认类别：铺装路面/右侧行驶/棕榈/苔原） |

> **重要含义**：此前"CLIP 视觉特征 +0pp，与零样本完全冗余"的结论是**基于一段从未执行的代码**得出的，**不成立**。修复后该模块首次真正生效，需重新评测。

### 3.7 根因分析：为什么一连串问题能同时进主干

| 根因 | 说明 |
|---|---|
| 编辑方式危险 | `d8fdc99` 用了脚本化的批量文本替换（sed 式），缺少缩进/语法校验，一次误删 100 行、一次错误缩进毁掉整个类 |
| 异常被大范围吞掉 | `try/except Exception: pass` 遍布增强模块，把 `NameError`/`AttributeError` 全部隐藏，故障表现为"没反应"而非报错 |
| 异步任务异常无出口 | `asyncio.create_task` 启动的任务异常无人 await，且被强引用持有 → 连 GC 警告都没有 |
| 缺端到端回归 | 只有前端编译检查，没有"提交前跑通一次真实分析"这一关，所以管线全挂也能推上去 |
| 提交信息与实现不符 | `d8fdc99` 声称"OCR 简化为纯语系判断，不再搜索"，但代码里 OCR 仍在做 Tavily 搜索（见 §4.1-3） |

## 四、未来规划

### 4.1 P0 · 立即（1 周内）

1. **复测修复后的真实准确率**
   在 `bench_hard`（31 张，71% 荒野）与 `bench50_hd`（45 张）上重跑，重点回答：视觉特征先验真正生效后，是否带来可测量的提升？——这是当前唯一"曾经被错误否定"的方案。

2. **建立端到端回归测试**
   一条命令跑通「起服务 → 提交 2~3 张图 → 断言 `status=succeeded` 且 `candidates` 非空、`facts` 非空」。纳入提交前检查，杜绝"管线全挂还能推主干"。

3. **梳理并收敛静默异常**
   把增强模块的 `except Exception: pass` 改为**记录一条 warning**（带模块名与异常类型），保留"不阻塞主流程"的语义，但故障可观测。同时给 `asyncio.create_task` 加统一的异常回调/日志。

4. **对齐 OCR 行为（需决策）**
   提交信息称 OCR 已"只判语系、不再搜索"，但实现仍在调 Tavily，UI 开关文案也写着"→ Tavily 搜索验证地名"。三处不一致，需明确最终形态：
   - A. 纯语系判断（免费、快、无外网依赖）
   - B. 保留 Tavily 搜索（有地名时更准，但依赖网络与额度）
   - C. 分档：有文字→判语系；识别出高置信地名→才搜索

### 4.2 P1 · 短期（2~4 周）

5. **荒野图专项**（当前最大短板：71% 的评测图是荒野，准确率显著低于城市街景）
   已验证"纯 CLIP 视觉特征与零样本冗余、纯线性探针会多数类坍缩"两条路都不通。剩余可行方向：
   - 引入**外部先验**（生物群系/植被带/地貌分区的离线矢量图层）做候选裁剪
   - 用**检索式**方法（图库 kNN）替代分类式，参考已跑通的 Netryx Hub 索引（莫斯科/纽约已验证可用）
   - 明确接受"荒野只给国家/大区级"并如实标注置信度，而非硬给城市

6. **用户反馈闭环做实**
   `feedback_analysis.py` 已有"错误率 >50% → ×0.7 / >30% → ×0.85"的先验校正，但样本量还太小。规划：反馈入库结构化（真值国家/城市、误判项、是否荒野），积累到一定量后做**按图类分档校正**，并输出可视化混淆矩阵。

7. **性能优化**
   - 冷启动 ~56–80s：评估权重常驻/预打包或降级为"边用边加载"
   - 单图 12–20s：拆分耗时热点（模型推理 vs 增强模块），把增强模块改为可并行/可超时跳过

8. **中国模式打磨**
   已跳过国家级直推城市，但缺少中国专属评测集。规划：构建 50~100 张中国街景（含县城/乡镇）评测集，量化后再谈优化。

### 4.3 P2 · 中期（1~2 月）

9. **评测体系升级**：从"国家 Top-1"升级为**国家准确率 + 200km 内命中率**双指标（已在 `geo-bench-data/retest0912` 有雏形），并固定一份**不可见测试集**避免调参过拟合。
10. **城市级检索**：把 kNN 检索融合（图库向量）作为城市级的第二意见，与 CLIP-B/16 加权融合；先小规模验证再决定是否铺开。
11. **打包分发回归**：PyInstaller 产物需在干净机器上验证"模型内置 + 首次启动 + 无需 Python"全链路。

### 4.4 明确不做（负结果清单，避免重复投入）

- ❌ TTA 多裁剪、温度校准（+0pp，已证伪）
- ❌ 纯 CLIP 视觉特征维度继续加码（与零样本冗余，若 §4.1-1 复测仍为 +0 则彻底关闭）
- ❌ 小样本本地线性探针（多数类坍缩，负收益）
- ❌ MegaLoc / 仅覆盖少数城市的社区索引（荒野无效）
- ❌ 云端 VLM 融合用于荒野（无增益、耗时、有成本）
- ❌ 百度识图（能力边界不清且已按需求移除）
